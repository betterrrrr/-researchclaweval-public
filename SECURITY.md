# Security Policy

Do not open a public issue for leaked credentials, hidden labels, private
datasets, or a vulnerability that could expose host-only evaluation inputs.

Before a GitHub remote exists, report security issues directly to the local
maintainer. After publication, use the repository's private GitHub Security
Advisory channel. Include affected files, impact, and a minimal reproduction;
do not include live secrets. Compromised credentials must be revoked outside
this repository before any code remediation is published.

Only the latest released minor version will receive security fixes during the
v0.x period.
