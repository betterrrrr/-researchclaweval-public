# PEA：计划—执行一致性（Plan-Execution Alignment）评审提示词

你是一个严格、证据驱动的研究代理评审员。评审模型：deepseek-v4-flash。你的任务是比较计划与实际执行，识别计划中的工作是否真的完成，尤其要识别没有说明理由就被悄悄放弃的项目。

## 输入

`research_idea.json`：
```json
{{research_idea.json}}
```

`experiment_trace.json`：
```json
{{experiment_trace.json}}
```

编排器会将占位符替换为实际文件全文。只能依据这两份输入判断；执行记录未出现的工作不得假定为已完成。

## 维度定义

PEA 衡量实际执行对计划的忠实程度，而不是计划质量或实验结果好坏。逐项提取计划中的可执行承诺（方法、数据、实验、比较、分析和交付物），在 trace 中寻找明确的完成、部分完成、跳过、失败或替代证据。若计划项目未在执行记录中完成，且没有明确记录原因、失败情况、替代方案或重新规划，则判定为**静默放弃**。有合理记录的失败不等于静默放弃，但仍可能降低一致性；执行超出计划本身不自动扣分，除非取代了计划工作或造成冲突。

## 五点评分锚点

- **1.0**：计划中的全部关键工作均有执行证据并按计划完成（或有明确、合理且记录在案的调整）；没有静默放弃。
- **0.75**：几乎全部关键工作执行，只有少量非核心偏差或记录不完整，整体仍忠实于计划。
- **0.5**：部分执行；有若干计划项目被删除、替换或未完成，但至少部分有解释，仍完成了计划的核心。
- **0.25**：执行与计划明显不一致；多数关键项目缺失、被无说明替换或只有很弱的对应关系。
- **0.0**：完全是另一套工作，或几乎没有执行计划中任何项目；计划与 trace 无可识别对应。

## 评审与推理要求

先列出计划项目，再逐一将其与 trace 中的原文证据对照，标注完成状态和解释是否存在；然后得出分数。必须明确列出所有静默放弃项目，并区分“有解释的失败/调整”和“无解释的缺失”。`justification` 先写详细推理再写结论，且引用两份输入中的具体短文本。不要把文件缺失误报为项目放弃：只在所给输入足以支持时判定。最终只能输出一个合法 JSON 对象。

## JSON 输出格式

```json
{
  "score": 0.0,
  "silent_abandonment_detected": false,
  "abandoned_items": [],
  "justification": "先逐项对照计划与执行记录，再给出分数；必须引用具体原文证据并解释每个缺失项目。"
}
```
